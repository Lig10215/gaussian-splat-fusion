# 故障定位

| 表现 | 首先定位 | 处理与验证 |
|---|---|---|
| 查看器无法导入 | 记录实际报错/日志，检查 binary格式、字段名/类型、SH阶数、激活、点数/长度、NaN/四元数，核对是不是预期文件 | 新文件 normalize/validate，最小已知合法GS验证查看器；不要先改点数头或宣称中文路径必然有问题 |
| 双红墙、双台阶、两份文字 | source分开渲染，确认变换、导出缩放、同一实体是否两来源重复保留 | 修配准或扩大准确的实体所有权边界；保留一份真实结构，不用透明混合掩盖重影 |
| 近看文字消失、斜看变色 | 同机位对比原始来源，trace真实可见贡献点，检查遮挡、alpha与SH | 只在证据充分的文字原点上修局部材质，保护墙沿；不增加照片卡片/新字体/复制标牌 |
| 屋顶/水泥楼板透出室内 | 查表面被裁、中心越界、协方差穿越、薄弱采样、中心排序 | 先恢复权威原点，再边界约束或有依据的薄层支撑，全场景hidden recolor重测 |
| 遮挡测试通过但肉眼漏 | 是否空ROI、零隐藏点、只渲染了补片、错误相机/版本、把失败像素排除 | 绑定model/config hash，非空门槛，完整场景；真实查看器相同角度再验 |
| 白雾/暗色浮影 | 来源是否过曝/欠曝、空气点与墙体混合、巨型高斯、多视图支持 | 限定空气ROI和可追溯点，小步清理；暗处真实神像和柱梁不可按色删 |
| 一楼神龛/红柱/碑细节不见 | ownership是否覆盖过大，低处航拍替换是否抹掉实体，地面来源是否零贡献 | 按实体三维ROI恢复地面原点；用地面单独模型做同机位对比及required_rows |
| 地面出现大片光滑照片/拼接条 | 是否用了投影贴图、复制平面、过度support覆盖 | 回到航拍原始铺地；支持薄层只置于下方，不替代可见真实纹理 |
| 植被错位/建筑后黑洞 | 航拍原植被是否误删，叠加两次或宽泛区域归属错误 | 按权威航拍恢复原始位置与材质，正反方向检验；不生成虚构树冠 |
| 本来真实门洞/楼梯被填 | 取了凹区域凸包，生成平面超出测量范围 | 拆凸块并明确孔洞/通道；通过室内外实际路径检查 |
| ICP低误差但建筑错层 | 对称柱廊错误对应、重复纹理、植被主导，初值错误 | 回到空间分布控制点与独立机位，不继续扩大ICP阈值求“收敛” |
| 旋转后颜色不对/高斯方向异常 | 是否只移动XYZ、SH通道packing错误、wxyz/xyzw混淆 | 同步变换尺度/旋转/SH，运行selfcheck任意Sim3辐射和协方差不变量 |
| Windows改名/覆盖失败 | memmap句柄仍开、查看器占用文件、输出已存在 | with关闭输入和回读映射，输出新版本；不要杀用户程序或覆盖源文件 |
| 大文件内存/渲染慢 | full-scene需要原点与投影数组；巨型高斯覆盖大量像素 | 流式检查/融合，先低分辨率定位，限定相机；最终全场景验收不要只裁点测试 |

本案例没有保存可证明历史查看器报错根因的原始日志，因此上述是排查顺序，不是声称当时一定由某字段或路径引起。

本工具不包含 ExplorerWin.exe 的逆向或 CUDA 内核替换。若另有该任务，应读取实际二进制/源码与相应 REA 技能，形成独立验证范围，不能因本融合工具可在 AMD 电脑上用 CPU 运行就宣称完成 GPU 移植。
